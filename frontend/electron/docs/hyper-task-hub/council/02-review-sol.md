# HyperTaskHub cross-review · Sol

Proposal references use the member and section number, for example `Astra §4` refers to `01-proposal-astra.md`. Code paths are relative to `frontend/electron` unless specified.

## Agreements

- **Astra §1 and Sol §1.** An action can be completed, an occurrence can reserve time, and a message or article can support either. One meeting can produce several actions. Each action needs a stable identity, and each imported fact needs provenance.
- **Astra §4, Opus §4 and Sol §4.** Keep source authority and personal planning state separate. Show cached records offline with last success and coverage per source. Preserve local decisions across refreshes.
- **Astra §5, Opus §5 and Sol §5.** Rank deterministically, explain the inputs, and let users explicitly change the plan. Reordering during interaction should wait, as Opus proposes in §8.
- **Astra §6, Opus §6 and Sol §6.** Open a brief from the meeting, cite related work and correspondence, and return evidence even with the AI endpoint disabled. I accept Opus's sheet and Astra's restriction on attendee-only mail matches.
- **Astra §§2, 7, Opus §8 and Sol §§2, 7.** English and Hebrew need extraction fixtures and display checks. Preserve the original evidence span through normalization. Isolate inline names, Jira keys and times when direction changes.

## Conflicts

1. **Unified model and IDs — compromise.** `Astra §1` uses local UUIDs and scoped observations with durable field origins. `Sol §1` adds requester, assignees and edge provenance. `Opus §1` flattens each source to `kind` and `externalId`, with dates as ISO strings. Adopt Astra's persisted shape with Sol's planning fields. Key observations by connector account and native scope. Jira uses instance and numeric issue ID, Newsletter uses connection/project/task, native rows use workspace/database/row, and Outlook uses store-scoped IDs with separate occurrence keys. Scope a mail candidate to an individual action span. Opus gets a flat projection with opaque source handles, primary-source selection, and typed civil dates or instants.

2. **Status vocabulary — compromise.** `Astra §1` uses `review/ready/doing/waiting/done/dismissed`. `Opus §1` uses `triage/next/in_progress/waiting/done/dismissed`. `Sol §5` uses `ready/done/waiting` as planner inputs. Keep Astra's persisted workflow, with Opus's labels in the view and raw source status alongside. Derive eligibility from workflow, source completion, snooze, release time, and verified predecessors. Done for me clears the personal queue. A successor needs completion from the system that owns its predecessor, including the Hub for local actions, or an explicit dependency resolution.

3. **System of record, sync and writes — compromise.** `Astra §4` proposes encrypted observations and durable decisions, with purge on revocation. `Sol §4` retains confirmed excerpts and proposes more frequent availability and Newsletter polling. `Opus §§4, 7` allows optional Hyper-Kanban mirroring and approval-triggering drags. Keep the encrypted main-process store and separate ledgers. Purge revoked source payloads and derived briefs, retaining owner-authored actions and opaque suppressions. Share Jira's refresh trigger where practical, start Newsletter at 15 minutes, and coalesce Outlook reads on focus or presence recovery plus a five-minute refresh while active. Commit explicit coverage and completed cursors with the data. First-release drops change local state. Source editors handle external edits.

4. **Ranking runtime — compromise.** `Opus §8` allows main or a worker. `Astra §§4–5` owns the main store but leaves execution open. `Sol §§5, 8` supplies pure functions in shared code. Run them from main on a versioned snapshot of normalized inputs, outside IPC validation and connector I/O. Move computation to a main-owned worker if profiling shows main-loop stalls. Use a scoped clock and reject results after a scope or snapshot change. Keep drag feedback local while recomputation is pending.

5. **Score formula — concede.** `Sol §5` weights ten signals, including sprint, Jira priority, critical path and quick effort. `Astra §5` weights slack, owner importance, unblocking and age at 45/25/20/10. `Opus §5` defers weights and asks for separate axes and signed deltas. Start with Astra's four inputs. Use `clamp(1 - slackMinutes / 480)` for urgency, owner priority mapped to `0/.33/.67/1`, `min(verifiedOpenSuccessors, 5) / 5`, and `clamp(ageDays / 28)`. Slack counts remaining free working minutes before a confirmed due or prep deadline, less estimated effort. Use a labeled provisional estimate for planning and mark slack unknown when availability is missing. Unknown signals contribute zero with a reason and fixed denominator. Treat a civil due date as the end of its source day. Return urgency and importance separately, and use the same editable importance scale for the Matrix. Add optional signals only after verifying coverage and benefit on labeled examples.

6. **Scheduling and first recommendation — hold.** `Opus §5` fills by rank and reserves prep. `Astra §5` places fixed pins and tries deadline-critical chains first. `Sol §5` compares score-first and effective-deadline-first passes, each enforcing precedence and contiguous fits. Keep both passes behind one interface and choose by weighted on-time work due today, then total placed value, then stable pass order. Pins change queue order. Fixed blocks reserve time. A future predecessor placement can support a forecast, while a Start action requires actual readiness. Recommend the earliest feasible block, including its start time when later. For example, a 30-minute renewal due at 10:00 can take the only pre-meeting slot even if a 45-minute checklist has a higher score. Show misses, and require a usable coverage window or manual availability for timed suggestions.

7. **Triage and auto-accept — hold.** `Astra §2` gates flagged follow-ups behind opt-in and measures precision before enabling background suggestions. `Sol §2` requires confirmation of inferred actions. `Opus §2` suggests a confidence threshold and exempts meeting requests alongside explicit assignments. Import opted-in verified assignments and supported active flags directly. An invitation supplies availability and a possible brief. Any inferred agenda or mail action goes to Triage, regardless of confidence. Remember dismissal by scoped action fingerprint so a second request in the same message can survive.

8. **Dedupe — compromise.** `Astra §3` uses exact identity, validated Jira mirrors and corroborated fuzzy matches. `Sol §3` adds explicit field conflict resolution, edge redirection and undo. `Opus §3` offers unlink and describes fuzzy matches below certainty as suggestions. Automatically collapse exact observations and verified mirror aliases. Require owner confirmation for fuzzy or action-level merges. Preserve distinct asks about the same issue, retain every source reference and rejected suggestion, and make merge and split reversible. Revalidate edges and report cycles after an identity change.

9. **Meeting prep — compromise.** `Astra §6` favors the next accepted or organizer-owned meeting within 24 hours and topic-gated mail. `Sol §6` adds evidence scoring, a bounded series lookback and refresh before the meeting. `Opus §6` adds a sheet, prior notes and a readiness ring that can turn ready on open. Build on demand and precompute within 24 hours for accepted or owner-organized meetings. Prioritize explicit links, then verified issue keys, series and topic evidence. Keep attendee-only open work in its own small list. Invalidate changed occurrences and mark stale sections. Track Viewed separately from prep completion. Enable optional tool-free summarization only for selected, approved evidence.

10. **Views and placement — concede.** `Astra §7` separates Review, Board and Today. `Sol §7` suggests Board/Today first and later workload. `Opus §7` leads with Focus, puts Triage in Board, and adds Matrix, Timeline and Meetings. Use the `taskhub` page with Focus as the default Today plan, a Board with actionable Triage and overflow, and the meeting sheet reachable from Focus and the compact HyperHome bar. Put capacity and unplaced work in Focus at launch. Add the Meetings index, Matrix and dependency Timeline in the next visual phase.

11. **IPC and store ownership — compromise.** `Astra §8` describes narrow read IPC and preload, `Sol §8` leaves the projection in a repository, and `Opus §§8–9` wants typed feedback and one renderer store. Astra owns the scoped main store, revisions, typed IPC and preload. Sol owns the non-rendering `useHyperTaskHub` store and client, exposing snapshots, local feedback, refresh and typed open-source actions. Main validates sender, scope, target and revision. The renderer reconciles acknowledgements and clears state on account or workspace changes.

12. **Phase plan — compromise.** `Astra §8` starts Jira/native, `Opus §9` pulls all structured sources plus Focus into phase 1, and `Sol §8` sequences board, planning, then prep. First ship an internal Jira/native Board slice proving offline restart, dedupe and account isolation. Add Outlook mail and calendar, native calendar and Newsletter Gantt with coverage fixtures, bilingual Triage, Focus and the deterministic brief before calling the charter's first release complete. Follow with the secondary views, then evaluate optional AI and confirmed external writes independently.

13. **File names and owners — concede.** `Astra §8`, `Sol §8` and `Opus §9` name overlapping contract, schedule and brief files differently. Assign `src/shared/HyperTaskHubTypes.ts` to Astra and use Opus's main service split under `src/main/hyper-task-hub/`, with Astra owning `HyperTaskHubStore.ts`, `HyperTaskHubService.ts`, `HyperTaskHubIpc.ts` and `HyperHub*Source.ts`. Sol owns shared `HyperPriorityEngine.ts`, `HyperDayPlanner.ts`, `HyperMeetingBrief.ts` and their fixtures, plus renderer `useHyperTaskHub.ts` and `HyperTaskHubClient.ts`. Astra owns optional main summary transport. Opus owns `HyperTaskHubPage.tsx`, every rendered view and visual test, and all navigation and HyperHome wiring.

## Gaps

- Define native calendar field mappings for reservations, milestones and dates with no end. The existing view synthesizes one hour for a timed row without an end. That display fallback needs an owner-approved policy before it can reserve time. `src/renderer/features/hyper-database/views/calendar/HyperCalendarData.ts:38`.
- Name which authorized document sources the first brief can resolve, how access revocation invalidates cached briefs, and how the brief labels an attachment reference when content is unavailable.
- Define the date and locale policies for split workdays, holidays and DST transitions. Decide how long availability can age before the Hub downgrades timed recommendations, and show when missing estimates or dependencies make the next action provisional.
- Define what a multi-day workload view measures. Separate personal capacity and unplaced effort from Newsletter chart duration, and specify where hours for shared or unassigned work appear.
- Specify scope-reset and purge tests for OS encryption unavailable, offline restart after sign-out, and permission changes mid-fetch. Include both source coverage and recommendation quality in release acceptance.

## Draft decisions for the consensus spec

1. Persist scoped observations, stable action UUIDs and separate occurrence IDs in an encrypted main-process store with a durable personal ledger.
2. Import verified assignments and opted-in flags, review every inferred action, and require confirmation for fuzzy merges.
3. Use a four-signal explainable score and compare score-first and deadline-first plans against confirmed availability and dependencies.
4. Recommend the earliest feasible action and show its start time, placement reason or blocker.
5. Build cited local meeting briefs from authorized evidence and track Viewed separately from prep completion.
6. Ship Focus, Board with Triage, the meeting sheet and HyperHome links with external changes handled by source editors.
7. Assign ingestion and IPC to Astra, ranking and brief logic to Sol, and all rendering and visual tests to Opus.
8. Start implementation after Astra, Sol and Opus sign the same version of the consensus spec.

## Objections

Paths below are relative to `frontend/electron`.

- **Flag and history claims need a new read operation.** The bridge lists Inbox, Sent or Drafts, up to 50 matches. It sorts Inbox/Sent by received time, examines at most 500 candidates and returns a bare array. Summaries include unread and importance. Neither summary nor detail exposes flag state, flag due date or conversation ID. A 14-day request can miss a flag placed today on older mail. Require a modified-time continuation through ties, explicit exhaustion and an active-flag inventory. Until then label bounded scans partial and suppress automatic "no reply" conclusions. See `src/main/HyperOutlookSchema.ts:41`, `src/main/HyperOutlookSchema.ts:65`, `src/main/HyperOutlookScript.ts:705`.
- **I would narrow my own invitation join.** Calendar occurrences include original start in their key. Invitation detail can return the appointment EntryID alone. Verify the occurrence before attaching evidence. Calendar listing silently stops after 2,000 scanned occurrences and omits cancellations, so even 1,999 returned rows can represent a capped scan. Add coverage metadata before declaring gaps free. See `src/main/HyperOutlookScript.ts:57`, `src/main/HyperOutlookScript.ts:334`, `src/main/HyperOutlookScript.ts:601`.
- **Prep needs a privacy check before indexing.** The calendar masks sensitivity value 2. The mail protection helper covers sensitivity ≥2 and protected message classes, yet a protected mail summary can retain subject and sender, and detail can enumerate attachment names outside the body-protection check. Keep protected mail out of indexes and briefs. Return busy intervals alone for confidential/private events. Attachment names and sizes support citations to the parent message only. Opus's "Open in Outlook" also needs a typed mail-open operation, since existing event open resolves against the default calendar. See `src/main/HyperOutlookScript.ts:53`, `src/main/HyperOutlookScript.ts:89`, `src/main/HyperOutlookScript.ts:182`, `src/main/HyperOutlookScript.ts:220`, `src/main/HyperOutlookScript.ts:734`, `src/main/HyperOutlookIpc.ts:11`.
- **Connector limits affect the planner.** Jira's dashboard search omits sprint, remaining time and blocking links, and its default all-issue cap is 10,000. Mark those signals unknown until a scoped read provides them. Newsletter Gantt project reads slice a returned chart locally. Fetch each project revision once. A single-task PATCH sends changes without the chart replacement's expected-version guard. Defer external date drags. See `src/renderer/features/jira/data/models/jira-issue.ts:71`, `src/renderer/features/jira/data/jira-api-client.ts:23`, `src/main/HyperBotsNewsletterTools.ts:119`, `src/main/HyperBotsNewsletterTools.ts:145`, `src/main/HyperBotsNewsletterTools.ts:167`.
- **ReUI supports most of the proposed interactions.** Kanban provides a keyboard sensor and delegates moves to the consumer. Its drop handler can record local feedback. The calendar supports day view and per-event read-only interaction. Gantt accepts dependency IDs, but the native database view disables lines. Opus can draw verified edges in a Hub wrapper. Sol must supply criticality and trustworthy edges. See `src/renderer/components/reui/kanban.tsx:227`, `src/renderer/components/reui/kanban.tsx:520`, `src/renderer/components/reui/event-calendar/event-calendar-types.tsx:6` and line 59, `src/renderer/components/reui/gantt/gantt-types.tsx:115`, `src/renderer/features/hyper-database/views/HyperGanttView.tsx:124`.
- **The ownership correction applies to my proposal too.** Strike the Neon assignments in Astra §8 and Sol §8. Use the Hyper-prefixed client filename above in place of Opus's `hyper-task-hub-client.ts`. Keep existing identifiers and upstream notices when reusing components. See `docs/hyper-task-hub/council/00-CHARTER.md:28` and `../../AGENTS.md:3`.

## Draft decisions for the consensus spec

1. Give each action a stable Hub UUID and each observation a scoped native key, revision and evidence role.
2. Let source records govern external completion and the local ledger govern triage, personal status, links and plans.
3. Import verified assignments in selected scopes and review every text-derived obligation individually.
4. Publish scope-checked snapshots with explicit coverage and preserve personal decisions across cache eviction.
5. Run Sol's deterministic ranking and two-pass planner in main and recommend the first feasible ready block.
6. Build occurrence-specific briefs from authorized local evidence and require an explicit action to summarize selected excerpts.
7. Ship Focus and Board first, with Opus as sole UI owner and Astra as sole IPC and renderer-state owner.
8. Gate implementation on three signatures for the same spec version and gate broader Outlook import on classic-profile verification.

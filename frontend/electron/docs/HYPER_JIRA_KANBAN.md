# Jira background sync and Hyper-Kanban

The signed-in desktop shell mounts HyperJiraBackgroundSync. HyperJiraRegistry owns one store/repository/cache and one reference-counted scheduler per user; the Jira tab and Settings use that same store. Settings/cache load once. An incremental sync starts 3.5 seconds after mounting, then checks every five minutes and on window focus when the last successful sync is at least five minutes old. The store's sync lock includes the Kanban copy, so manual and background searches never overlap. Unmounting on sign-out or user switch clears timers/listeners and invalidates board writes. Failures stay in the dashboard state without background toasts.

Every successful sync copies the cached project/JQL result (independent of temporary dashboard search/category/assignee filters) into the current workspace's board returned by ensureHyperGeneralKanban. No additional board is created. If the workspace/backend is unavailable, copying silently retries on the next successful sync.

The grouping field follows HyperBoard's rule: database groupSettings.items[0].fieldId, falling back to the first group fieldId. Single-select options are read from that actual field. Matching ignores case, spaces, hyphens and underscores: new/unknown -> To Do (also Backlog/Open/New/Not started); indeterminate -> In Progress (also Doing/Started/Working/Active); done -> Done (also Completed/Closed/Resolved/Finished). A canonical option is created only when no match exists. Unsupported grouping types, such as a user-selected checkbox, are skipped without changing the board's grouping.

Cards use the existing JiraDatabaseMapper columns, including Jira Key, Jira Link and Jira Updated, plus the primary title. All database rows are scanned, including rows hidden by board filters. Jira Key deduplicates across restarts and full refreshes; a matching Jira Link identifies source ownership. Unrelated or conflicting-source cards are untouched. Equal Jira Updated timestamps skip every card write, preserving manual title changes and drags until Jira changes. Updates write the timestamp last to retry partial failures; creates include the key and timestamp in the grouped row operation. Missing issues and existing cards are never deleted.

Settings → Connections → Jira exposes Add Jira issues to Hyper-Kanban, default on. The per-user shared-preferences key is hypertask.jira.<userId>.addToHyperKanban (false opts out). It is independent of the existing config/cache keys and does not change Hyper-Bot's connection config. Opting out stops future board additions/updates without removing cards; Jira background sync continues.

Local validation uses Vitest fake timers, fake Jira transports and an in-memory board gateway. Real Jira, native backend card persistence, focus behavior in Electron, and the final visual layout require review in the running app.

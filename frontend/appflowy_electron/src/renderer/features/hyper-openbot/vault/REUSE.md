# Native Vault

Upstream: OpenBot f8af37ab73e96784f174a11104505a965e722cab, MIT, Copyright (c) 2026 CopilotKit. The full notice is in LICENSE.OpenBot. HyperTask is developed by NaveDanan.

- `HyperVaultApi.ts` adapts `app/src/lib/passwords/queries.ts`, `mutations.ts`, `app/src/lib/credentials/queries.ts`, `mutations.ts`, `form.ts` and `app/src/lib/deployment/queries.ts`. Contracts verified against `server/src/app.ts` credential routes and `server/src/passwords/routes.ts`. Calls use the main-owned transport. No query mutation cache retains submitted secrets. Fixed error messages prevent echoed request bodies reaching the UI.
- `HyperVaultSection.tsx` adapts `app/src/routes/_authed/settings/vault.tsx`, `settings/_personal/vault_.new.tsx`, `app/src/components/vault/vault-page.tsx`, `saved-logins.tsx`, `app/src/components/manage/credentials-page.tsx` and `new-credential-page.tsx`. Personal-edition gating, disabled password-manager state, empty lists, deletion, revocation, model provider selection, connector validation and active-key replacement warning remain. The form uses uncontrolled password input cleared before awaiting submission. Native local sub-navigation replaces upstream router navigation. There is no edit or reveal flow upstream. Deletion and revocation act immediately as upstream does.
- `HyperSignInForm.tsx` adapts `app/src/components/passwords/sign-in-form.tsx`. Three-second polling stops at terminal states. Typed login, verification code, saved-login confirmation, takeover, finish and decline retain the upstream paths and bodies. Password/code inputs reset before the request. `onOpenBrowser(botId)` is a typed integration prop for the computer-browser area; the lead wires navigation. Without it, takeover instructions and completion remain available but no browser navigation button is shown.
- `index.ts` exports the native section, form, API and contracts for other areas, especially transcript/computer-browser integration. `hyperStoreMcpToken` ports the optional MCP-token helper from upstream credentials mutations for plugin setup.
- `HyperVault.test.tsx` tests mocked paths/bodies, storage non-use, safe errors, initial loading, personal gating and replacement warning. `HyperSignInForm.test.tsx` exercises terminal/code/takeover states and real form handlers with cleared login, code and key inputs before submission, including failed key writes and no browser storage writes. The shared policy test adds allowed families and traversal/other-family refusal.

The legacy `settings/passwords.tsx`, `settings/credentials.tsx` and `settings/credentials_.new.tsx` only redirect to Vault upstream; the native sidebar uses the canonical Vault entry. `settings/connected-accounts/index.tsx` and `$key.tsx` only redirect to Connections, preserving OAuth query parameters. Those web callback redirects are not recreated in this renderer, which has no web router or OAuth callback ownership. The existing Connections area owns connected-account behavior. Native legacy-address/OAuth callback routing remains an integration responsibility.

Visual adaptation uses existing Button/Input components, token colours, bordered rows and a separate add-key screen. Native select and checkbox controls replace upstream UI primitives. No dependencies added. No Electron app or live backend was used.

## Comparison before implementation

Native single-Bot chat already covered draft retention, stable retry IDs, attachment staging, run recovery, model selection, approvals, durable history and inert Markdown. It created multi-Bot channels as single-agent CopilotKit sessions. No native group transcript, group membership, group addressing, multi-recipient selector or Team Bot consent card existed.

## File mapping

- HyperConversationsApi.ts adapts app/src/lib/groups.ts and the consent mutation from app/src/lib/team-bots.ts. Query caching is replaced with native component lifecycle polling; API payloads and first-message rollback from app/src/lib/channels/start.ts are preserved.
- HyperGroupChat.tsx adapts app/src/components/channels/group-chat.tsx, group-people.tsx and team-bot-consent.tsx. Uses HyperTask Button/Input, existing inert HyperMarkdown and HyperComposer. Addressing uses an explicit recipient selector. Group runs stay on the server and do not bind the first Bot to CopilotKit. Polling follows upstream's active-turn and bounded first-reply rules. Failed sends retain the composer and retry ID. Identity comes from server /api/me and never from a guessed local user.
- HyperNewConversationSection.tsx adapts recipient selection from app/src/routes/_authed/_app/channel/new.tsx. Selection order determines Bot reply order. Creates on Start rather than first send. No web router, shell or global CSS imported.
- index.ts exports the native components and API contracts.
- HyperConversationsApi.test.ts covers contracts, rollback and polling. HyperGroupChat.test.tsx covers loading, refusal and consent failure states.
- ../HyperOpenBotPage.tsx dispatches multi-Bot channels to HyperGroupChat and creates them through /api/groups. Existing single-Bot recovery remains intact.
- Shared policy adds groups, team-bots and me, verified against server/src/app.ts route mounts. The me family supports the current-user read used for consent and membership permissions. No credentials are retained.

## Group questions follow-up

HyperGroupQuestions.tsx adapts app/src/components/approvals/question-notice.tsx and app/src/lib/approvals.ts. HyperGroupChat polls the inbox every ten seconds and on working-state changes. Replies addressed to the asking conversation Bot answer its question; another recipient receives a normal group message. Answer and dismissal use server-authoritative writes and retain the question after refusal. Multipart answers retain upstream label/option/free-text serialization, with all decisions displayed together in a native fieldset rather than upstream's paged questionnaire. No answer is persisted locally. HyperGroupQuestions.test.ts covers handoffs, channel isolation, exact transport contracts, failures and multipart serialization. Approval routes were already allowed; no new family is needed.

HyperDeliveryApi.ts maps app/src/lib/delivery.ts; HyperDeliveryControls.tsx maps app/src/components/delivery/reaching-you.tsx. Destinations are scoped to the current conversation, so the current channel replaces the upstream conversation picker. Phone verification, link expiry, unavailable transports, STOP state, device removal and delivery history use server results. Phone/code/challenge and link commands stay in component memory. Native inline controls replace the upstream dialog. Minimal main-process edit synthesizes the fixed upstream anti-CSRF headers for exact audio/voice endpoints, without accepting arbitrary renderer headers.

## Shared draft/navigation integration

HyperInitialDraftTransfer.ts consumes onboarding/HyperHomeApi.ts's HyperInitialDraft through the parent conversation cache and original channel attachment/send contracts. Creation, every upload and the optional send are awaited. The Home component stays mounted until success. A failed initial send retains the channel, uploaded file references and stable message retry ID; the Home File objects remain in memory. Duplicate starts refuse. Navigation, unmount and service loss cancel the transaction and prevent late navigation. submit:false populates text, command IDs and uploaded attachments without sending. Groups support text population/send and explicitly refuse attachments/skills, matching the upstream group composer capabilities. HyperInitialDraftTransfer.test.ts and HyperInitialDraftReceiver.test.ts exercise the transaction, real upload helper, File identity, failures, retries and cancellation. HyperOpenBotSectionContext supplies initialDraftSupported and native destination navigation; the implementation retains auth/service gates and never reroutes the Home message.

### Cross-area interfaces and ownership dependencies

- **bot-tabs owns Sharing.** It must provide a native Bot Sharing destination accepting `{ botId: string, context: HyperOpenBotSectionContext }`. Upstream app/src/lib/team-bots.ts contracts: GET `/api/team-bots` -> `{teamBots,publishable}`; PUT `/api/team-bots/:botId/publication` body `{audience:'team'|'people',emails:string[],groups:string[]}`; DELETE the same publication path; POST `/api/team-bots/:botId/assignments` body `{group:string}`; DELETE `/api/team-bots/:botId/assignments/:group`; DELETE `/api/team-bots/consents` clears saved preferences. Refresh Bots, Team Bots and shared-use requests after writes. Conversations owns only the inline consent POST and does not duplicate publication/audience/assignment controls. Upstream `_app/team-bots.tsx` is a redirect to Bots, not a second management screen.
- **Nested destination consumers.** The parent context now supplies `navigationIntent?: {path:string}` and lazy sections receive `path?:string`. Settings already consumes `path` and legacy `/settings/activity?bot=...` works through it. Approvals currently ignores the supplied path and always initializes its Inbox tab; its owner must accept `/settings/notifications` as its Notifications tab and load delivery/routing on entry. Browser/connected-browser and Connections owners must consume retained nested IDs where they expose detail routes. This integration does not edit those owned folders or simulate clicking their UI.
- **Screens gallery allocation.** No `screens` registry entry or gallery default section exists on parent 4f536f3. `navigate('screens', {path:'/settings/components-gallery'})` retains the intent and reports the missing registration. Parent/screens owner must register a real gallery destination or name its supported replacement. Redirecting to Home would falsely discard the requested screen.
- **Generative transcript content.** HyperTranscript's `renderTool` seam remains the integration point. Subagent rendering is implemented here; authored/generative UI remains screens-owned. Provide a tool renderer receiving the tool record and `{channelId,threadId,agentId,onSend}` for native screen results; no remote HTML execution is added here.
- **OS speech recognition.** Live dictation uses the browser-compatible recognition interface already exported by computer-browser/HyperNarration. Upstream Tauri's macOS/Windows native recognizer cannot be called from Electron because no matching main/preload speech API exists. Provider-backed dictation and available Web Speech recognition work; a native-only recognizer requires a parent-owned main/preload interface. Unsupported recognition is hidden, as upstream does on unsupported platforms.

Tests cover reducer parity, actual composer queue ownership/restoration, channel socket lifecycle/denials/fresh reads, authenticated archive/outbox, initial model retry, question continuation/read marks, hotkey layouts, typed reveal, subagent contracts and turns finishing after navigation. Shared edits outside the primary owned UI are minimal integration changes to HyperConversationActions.tsx, HyperChannelPaging.ts, socket.ts, HyperOpenBotSections.tsx and main/hyper-openbot.ts plus main socket/header regression tests.

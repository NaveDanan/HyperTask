# HyperGantt implementation decisions

This surface inherits the HyperTask design specification and the binding Gantt brief. It wraps the vendored MIT ReUI Gantt; vendor source and notices are unchanged.

- **Persistence:** `hyper_gantt` stores start/end, colour, progress and assignee field IDs, scale, list width, and zoom. The user's explicit request to persist zoom takes precedence over the brief's session-only zoom rule. Writes use the foundation's `updateViewExtra`, which merges extra and retains `hyper_layout` and unrelated keys. Settings writes are serialized to prevent rapid controls from overwriting each other. An in-flight schema hydration cannot replace a newer field choice.
- **Date boundary:** the core codec uses seconds. All-day database end days are inclusive; ReUI ends are exclusive. Multi-day ranges add/remove one calendar day at that boundary. Equal start/end days are milestones. Day gestures retain the original clock times and `includeTime` flags for timed cells, including each flag in two-field mode. Range edits retain reminder IDs.
- **Commit gate:** the vendored synchronous update gate starts an asynchronous core write and returns adjusted timing. An optimistic overlay lasts until the controller finishes its successful write and cell refetch. A pending row refuses a second simultaneous date gesture. Two-field edits and clears compensate the first successful mutation if the second fails; failed compensation requests explicit inspection of both fields.
- **Actual ReUI knobs:** layout sizes use `metrics` and `treePanel`, with `treePanel.onWidthChange`. The toolbar composes `GanttNavToday`, `GanttNavPrev`, `GanttNavNext`, `GanttTitle`, and a controlled Base UI Select, omitting hourly Day. `timelineLines` uses the object form with horizontal and vertical lines because the `vertical` shorthand removes row separators. Scoped classes align the 65px name header, today pill, 32px column-menu slot and drag ghost, and pin the name column when the list scrolls horizontally. `offDays.className` removes the current vendor's default weekend hatch. A local zoom badge accompanies the vendored floating control.
- **Colour:** the foundation Grid is a placeholder and exposes no existing select colour map. A local mapping of the existing protobuf enum to Tailwind colour variables supplies user-data colours, with `--muted-foreground` for no status. No hex colours were introduced.
- **Fields:** date auto-picking waits for loaded date cells. Progress prefers a named number field, otherwise a checklist. Number values are fractions only when all loaded values are in 0–1; the numeric progress field is loaded for all rows to make that decision stable. Checklist slider edits round to a count of completed items and update them in checklist order. Assignee select names or text become initials avatars.
- **Loading:** title/date fields are indexed for every ordered row, so off-screen bars and milestones remain meaningful. Other mapped fields load initially for 50 rows and within a 180px viewport margin through the existing bounded controller cache. The vendored Gantt owns DOM layout, pane synchronization and gestures; it is not forked to add virtualization.
- **Details and menus:** the foundation has no row-detail opener. A local right sheet supplies title, date range, status, assignee and progress controls when those fields exist. Delete requires an AlertDialog. Row/bar context menus also expose Move up/down as alternatives to dragging. Title edits save on blur or sheet close; unchanged titles do not overwrite external updates.
- **Locales:** week starts follow `Intl.Locale` week information, with a fallback for older runtimes. ReUI and day gestures use the browser's local calendar/time zone.
- **Shared changes required:** the shared page's generic empty database screen intercepted every zero-row layout. Its condition now permits Gantt to render its own required empty/date-field states. `HyperDatabaseController.updateViewExtra` now retains the known view plus merged extra when the backend returns an empty acknowledgement instead of view metadata. Both changes are small and preserve other view behavior; the acknowledgement case has a regression test next to the Gantt files.
- **Verification limits:** the vendor clamps reverse-edge resize gestures to its minimum duration before proposing a write, so no artificial reversed-span destructive-ghost screenshot was manufactured. Invalid/reversed spans are covered at the mutation boundary. The foundation Grid body remains a placeholder; shared-cell persistence was checked through the live controller and reopening instead of a Grid cell screenshot.

Screenshot verification uses the supplied prebuilt Rust core, port 5204, and only the copied `support-gantt` scratch directory. Failed attempts to create an additional fixture through the existing foundation seed API were replaced with an already seeded spare Gantt database in that copy; no root checkout or original support data was changed. The shared browser's 2x captures were replaced with the documented Chrome harness driver to produce exact 1440×900 PNGs.

Commit author/committer use the foundation commit’s existing `HyperTask implementation agent <implementation@hypertask.invalid>` identity, passed only to the commit command because this worktree has no configured Git identity. No shared/global Git configuration was changed.

Reuse its bounded UI and lifecycle patterns only after checking their dependencies and fixing relevant review findings. This note delivers [issue #3](https://github.com/NaveDanan/HyperTask/issues/3). It changes no runtime behavior. [HYPER_OPENBOT_PROGRESS.md](HYPER_OPENBOT_PROGRESS.md) records the delivery sequence and review gates.

This is a source pin, not a tested or known-good release. All OpenBot links below use that SHA. HyperTask inspected at 2a5bbd3c5027f3b121d3ef010d806fca0f03bcb9. ## Baseline blockers

- OpenBot defaults to managed Intelligence. Its documentation describes a free, renewable 30-day local license and a local preview for macOS with Docker Desktop. Issue #4 requires original Intelligence locally. On a non-Mac host, support for that documented source-template preview is not established. Kubernetes evaluation requires amd64 nodes, default StorageClass and trial or production license. Whether the target host, entitlement, CLI and images support the baseline remains unverified. Do not assume the desktop's bundled k3d path proves Linux preview support. [README](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/README.md#intelligence-on-your-own-machine), [architecture](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/docs/architecture.md), [chart](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/charts/openbot/README.md).
- Source setup needs Docker, Bun 1.4+, an Intelligence project and API key, reachable API and gateway, a qualifying license for the selected installation, and a working model and credentials. Managed Intelligence needs no separate license token, but does not satisfy #4's local Intelligence criterion. The documented local command invokes the latest CopilotKit CLI without a version pin. Image access, model availability, entitlement and credentials have not been checked. [README source setup](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/README.md#source-setup), [environment](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/.env.example).
- No prompt, streaming, persistence or restart test was run. Record exact image digests, CLI and Intelligence versions and license terms during provisioning. A source SHA alone is not a reproducible runtime. [Compose](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/docker-compose.yml), [start script](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/scripts/start.sh).
- HyperTask's UI spec forbids adding npm dependencies for the redesign and freezes existing stores and behavior. OpenBot chat needs CopilotKit, AG-UI, prompt-area, Streamdown, TanStack and its own UI and styling. The user has authorized the OpenBot integration through epic #2. Add only the runtime dependencies needed for a proven slice, document that integration-specific exception to the redesign instruction, and keep existing UI primitives. Do not use that exception to replace global UI/CSS or install the entire OpenBot frontend dependency set. [HyperTask UI spec](https://github.com/NaveDanan/HyperTask/blob/2a5bbd3c5027f3b121d3ef010d806fca0f03bcb9/frontend/appflowy_electron/docs/design/HYPERTASK_UI.md), [OpenBot app manifest](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/app/package.json).

The live [Intelligence local-evaluation guide](https://docs.copilotkit.ai/intelligence/self-hosting-local), checked 2026-11-13, clarifies that the CLI accepts Linux with rootful Docker Engine, while Linux runtime evaluation remains unverified and outside the supported preview. This is a possible evaluation path, not a verified supported Linux baseline. It requires at least 4 CPUs, 12 GiB RAM and 40 GiB free storage. The [self-hosting guide](https://docs.showcase.copilotkit.ai/intelligence/self-hosting) also describes local Kubernetes/k3d validation with a valid Intelligence license. Resolve which original-service path is available before #4; do not treat the macOS preview statement as proof that original Intelligence cannot run locally on Linux. These live guides are separate from the frozen OpenBot source pin.

## Services, trust and data

[Architecture](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/docs/architecture.md) describes React to Hono API to CopilotKit runtime to AG-UI bot. Results stream back and tool calls return through server policy and audit before computer execution. Intelligence holds durable threads, realtime, memory and Learning; PostgreSQL holds OpenBot decisions, users, channels and policies. Groups map each bot to a separate Intelligence thread and retain a shared transcript. Do not map these stores onto HyperTask data paths or assume all conversation data resides in Postgres.

[app.ts](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/server/src/app.ts) mounts the runtime under /api/copilotkit with guards; [config.ts](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/server/src/config.ts) constructs allowed origins and Intelligence endpoints. [request-trust.ts](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/server/src/request-trust.ts) implements origin and single-user checks, and [intelligence-gateway-proxy.ts](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/server/src/intelligence-gateway-proxy.ts) covers the gateway proxy. The provider sends cookies and keeps Intelligence keys server-side. [Better Auth](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/server/src/auth/index.ts) supports sessions and configured identity providers; the example enables local single-user mode. Electron origin, cookie and WebSocket behavior requires testing with the selected serving strategy. An arbitrary file or custom origin cannot be assumed compatible; do not bypass guards.

[Compose](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/docker-compose.yml) publishes loopback ports and separates Postgres on a data network from the computer network. Defaults include pgvector/pgvector:pg17, busybox:1.37, SPIRE server/agent 1.15.1 and locally built openbot-server:latest, openbot-agent-computer:latest, openbot-supervisor:latest, openbot-agent-bot:latest and openbot-agent-langgraph:latest. These tags are not immutable digests. The script starts required services, migrates, and runs host API, worker and app; defaults include app 3010, API 3001 and Postgres 5432. Computer, supervisor and agent ports are configurable. The [worker](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/worker/src/index.ts) fires routine work and authenticates handoff via a shared secret. It is not the renderer or Intelligence.

The [computer](https://github.com/CopilotKit/OpenBot/tree/f8af37ab73e96784f174a11104505a965e722cab/agent-computer) runs a browser, files and shell with workspace/profile and supervisor options. Container reachability is a security boundary; compose explains why Postgres must not share the computer network and ports bind loopback. Preserve tokens, isolation and policy checks; ordinary containers share the host kernel unless an alternate runtime is configured. Optional app brokers, external OAuth, voice, extra agents and scheduling are not established prerequisites for smallest plain chat; validate the selected [start mode](https://github.com/CopilotKit/OpenBot/blob/f8af37ab73e96784f174a11104505a965e722cab/scripts/start.sh).

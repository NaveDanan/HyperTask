## Inline equations

Select text or place the caret, then choose Inline equation in the document toolbar. Save replaces the selection with one upstream-compatible formula atom. Activate an existing equation with a click, Enter or Space to edit it. Unwrap replaces that atom with its formula source. Cancel restores the captured selection when the document still matches. Locked pages allow inspection and source copying. Failed or uncertain writes retain recovery details without replaying the operation.

Live rendering permits 64 atoms per block and eight distinct formula parses per paint, with source and markup budgets. Oversized or malformed blocks use a read-only source fallback; Copy retains the complete source. Saving a 65th atom is rejected before writing. These limits protect responsiveness without rewriting stored content.

HTML, clipboard and PDF exports use trusted MathML with the bundled STIX font. PDF export rejects formulas that exceed the page or their containing column/cell, including excessive height. The rendered sample was inspected. Markdown exports inline formulas as readable, inert source spans carrying exact attributes; importing those spans restores editable atoms. Ordinary dollar-delimited text stays literal. Unsupported or conflicting formula data stops a portable export with a source-copy error. Block equations keep their existing Markdown representation.

## Time-property filters

Existing Time properties can be filtered using whole minutes, including negative durations. A value of 90 means 1h 30m. These are exact signed integer comparisons, without timestamp, timezone or clock conversion. Empty cells differ from zero. Equality, inequality, ordered comparisons and empty/not-empty conditions use the native operators. Creating or editing Time cells/properties remains a separate gap.

Changed criteria must contain a valid signed i64 decimal. Existing unsupported, future or legacy criteria remain inspect-only and keep their exact bytes. The native prefill path adds or subtracts one minute for strict comparisons, so new Greater-than(MAX) and Less-than(MIN) criteria are rejected before writing. Equality and inclusive boundary values are supported. Inequality and presence conditions do not prefill newly created rows. Native writes still lack compare-and-set protection against an unobserved concurrent client write.

## AI field concurrency

Before applying a generated value, the renderer checks the captured source, target, field options, row, workspace, account and edit permissions again. The existing native `UpdateCell` event has no compare-and-set parameter. These checks reject observed changes but do not make validation and writing atomic against another client. Multi-client protection requires a coordinated core/protocol change and server tests.

## Document drafts and recovery

Shared document sessions distinguish the workspace, account and storage/server context. Owner changes block queued operations and quarantine late replies. Failed drafts remain available to their original owner, and reads for AI context wait for that owner's pending document writes. Row-body AI sources use current row metadata instead of relying on the abbreviated view row list.

The error state offers Copy unsaved content and a confirmed Reload saved page action. Reloading reads saved content without replaying failed actions, and keeps the old draft if that read fails. All open panes sharing the session update after a successful reload. Scope/race tests and a native two-pane recovery fixture cover these flows. An operation already sent to the core may have an uncertain result; failed actions are not automatically retried.
